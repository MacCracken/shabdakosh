# P1 sweep — shabdakosh v3.0.4 (2026-09-01)

A second, wider pass over the same `src/**` scope and threat model, this time
covering **correctness, resource use and performance** alongside memory safety —
the 2026-07-05 audit was scoped to untrusted-input memory safety and found nothing
in these classes because it was not looking for them.

- **Method**: read every module end to end, then MEASURE rather than reason —
  a probe binary that reports wall time and `alloc_used()` delta per public
  operation over the 10,617-entry built-in dictionary, plus a depth probe that
  drives `prefix_search` at increasing word lengths until it faults.
- **Outcome**: 5 defects fixed (2 HIGH, 3 MEDIUM), 4 resource/performance defects
  fixed, hardening applied across the allocation and callback paths. Suite grew
  689 → 821 assertions; 132 of the new ones are regressions for these findings.

| # | Severity | Location | Class | Status |

## 1 · Non-NUL-terminated keys read as cstrs (HIGH)

`cmudict.cyr` interns base-dictionary words as `str_new(piece + s, wsep - s)` —
`Str` VIEWS into the packed `_cmudict_data` string literals. `str_len` is correct;
the bytes are **not NUL-terminated**. Six call sites took `str_data(key)` and passed
it to a cstr API (`str_builder_add_cstr`, `strlen` via `_shbdk_dupz`), which read
to the next NUL — the end of the whole ~22 KB piece. Measured:
`strlen(str_data(key))` for the 5-byte key `night` returns **22,525**, and
`shbdk_to_cmudict(shbdk_dict_english())` produced **128,695,456 bytes** (expected
~300 KB), each word followed by the packed tail of its shard
(`night|36,15,22;nightmare|…`). `to_ipa` and both `validate` report builders had
the same defect.

Not memory-unsafe — the read stays inside the static piece — but a silent,
total corruption of every text export of the built-in dictionary, i.e. of the
library's headline data. It survived three releases because the format tests only
export dictionaries built by `parse_cmudict`, whose keys *are* NUL-terminated.

**Fix**: `str_cstr()` (which copies and terminates) at all six sites; in
`_shbdk_phono_collect` the copy is hoisted out of the per-pronunciation loop.
**Regression**: `tests/format.tcyr` — a hand-built dict with a deliberately
non-terminated key must export only the key's own bytes, plus an end-to-end
size assertion on the real built-in dictionary.

## 2 · `prefix_search` stack overflow (HIGH, DoS)

`_shbdk_trie_collect` recursed once per byte of the trie path, so stack depth was
the word length. `shbdk_from_binary` accepts words up to u16 (65,535 bytes) and
`shbdk_parse_cmudict` imposes no limit, so the depth is attacker-controlled.
Measured: word lengths 1,000 / 10,000 / 60,000 succeed; **200,000 faults with
SIGSEGV (exit 139)**, and the old `plen + 65536` buffer cap meant even a legitimate
~63 KB word drove recursion to the edge of the 8 MB stack. A corrupt `.bin` plus
one `prefix_search` call was a reliable crash.

**Fix**: the walk is iterative over two preallocated frame arrays indexed by
descent level (a push/pop work-vec was tried first and measured slower). Depth now
costs heap proportional to the path, not call frames. **Regression**:
`tests/trie.tcyr` — 70 KB and 200 KB words both search successfully and come back
whole, and a short word alongside an 80 KB one returns both.

## 3-5 · lazy_open ceiling, portable lseek, merge aliasing

See the CHANGELOG entry for 3.0.4; each is fixed with a regression test.
Finding 5 was the top open item in `docs/development/backlog.md`.

## 6-9 · Resource and performance defects

Every one of these was found by measurement, not reading. The probe's arena
figures are the tell: a bump allocator never frees, so a per-call fixed buffer is
a permanent leak in a long-running consumer (vansh holds a dictionary for the
process lifetime).

| operation | before | after |
|---|---|---|
| `to_cmudict` | 1,780 ms / 539 MB arena | 18 ms / 2 MB |
| `to_ipa` | 1,892 ms / 540 MB arena | 18 ms / 2.6 MB |
| `to_pls` | 873 ms | 25 ms |
| `dict.validate()` | 317 ms / 67 MB arena | 56 ms / 3.4 MB |
| `prefix_search` ×100 | 16.1 ms / 7.0 MB arena | 6.3 ms / 0.8 MB |
| probe total arena | 1,194 MB | 48 MB |

Lookup — the benchmarked hot path — is unchanged at ~128 ns hit / ~153 ns miss,
including the new null-word guard.

## Conclusion

All nine findings are fixed and covered by regression tests, and the export path
(`to_cmudict` / `to_ipa`) is now benchmarked so a repeat cannot go unnoticed.
**No open findings.**
